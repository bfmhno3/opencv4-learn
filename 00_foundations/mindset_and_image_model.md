# 图像、像素与 OpenCV 的心智模型

## 目标

在开始写 OpenCV 代码之前，先建立一个稳定的底层理解：图像不是神秘对象，而是一个保存像素数据的矩阵。

## 第一性原理

### 1. 图像本质上是离散采样结果

真实世界是连续的，但相机拍出来的图像是把连续场景离散化后的结果：

- 空间被切分成一个个像素点
- 每个像素记录某种强度值
- 彩色图通常记录多个通道

所以，一张图就是一个多维数组。

### 2. 为什么会有 `(height, width, channels)`

对 OpenCV 来说，一张彩色图通常可以看成：

- `height`：有多少行像素
- `width`：有多少列像素
- `channels`：每个像素保存几份数值

例如：

- 灰度图：`(height, width)`
- 彩色图：`(height, width, 3)`

### 3. 为什么 OpenCV 默认是 BGR

很多图像工具默认使用 RGB，但 OpenCV 历史上采用的是 BGR 排列。它不是“更正确”，只是约定不同。

这意味着：

- 用 OpenCV 读取图像后直接显示给 matplotlib，颜色可能不对
- 做颜色转换前，必须清楚当前图像的通道顺序

### 4. 为什么 dtype 很重要

图像不是只有“形状”，还有“数据类型”：

- `uint8` 最常见，取值范围 0~255
- 浮点图可以用于更精细的数值运算
- 错误的数据类型会直接导致显示异常、计算截断或 API 报错

## Python 和 C++ 如何对应

### Python

Python 中最常见的是：

- `cv.imread()` 返回图像数据
- 图像通常表现为 `numpy.ndarray`

### C++

C++ 中最常见的是：

- `cv::imread()` 返回 `cv::Mat`
- `cv::Mat` 本质上也是矩阵容器，只是类型系统和内存管理方式不同

## 这阶段你应该重点观察什么

1. 一张图的 `shape`
2. 图像通道数
3. 图像 dtype
4. 取一个像素点时拿到的值
5. 坐标 `(y, x)` 和直觉中的 `(x, y)` 差异

## 常见误区

### 误区 1：把图像当成“黑盒对象”

正确思路：先把它看成矩阵，再去理解 API。

### 误区 2：忘记 BGR/RGB 差异

这会导致显示颜色不对，但代码不一定报错。

### 误区 3：只记 API，不理解输入输出

学习 OpenCV 最容易陷入“背函数名”。真正应该掌握的是：

- 输入是什么矩阵
- 输出变成了什么矩阵
- 中间发生了什么变换
