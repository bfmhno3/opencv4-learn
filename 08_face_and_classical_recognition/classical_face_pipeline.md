# Classical Face Pipeline

## 目标

把经典人脸任务拆成一个清晰流程，帮助你后续分别实现“检测”和“识别”两个实验。

## 检测和识别不是一回事

### 检测

核心问题是：

- 这张图里哪里有人脸？

输出通常是：

- 人脸框位置

### 识别

核心问题是：

- 这个被检测到的人脸是谁？

输出通常是：

- 预测标签
- 以及你对结果可信度的解释

## 一条完整经典流程

这个阶段建议你拆成两层来理解，而不是一开始就把所有步骤绑死在一起。

### 基线识别闭环（推荐先做）

`读取 train/val 样本 -> 灰度化与必要预处理 -> 标签组织 -> LBPH 训练 -> 验证集预测`

这一条链路的目标是先把“训练集 / 验证集 / 标签映射 / 预测结果分析”这条主线跑通。

### 完整检测到识别流程（后续再做）

这一层不要再把它理解成“拿到一张图之后立刻训练”，而要理解成一个更完整的数据准备与识别工程。

你可以把它拆成两段：

#### 训练准备流水线

`训练图像 -> 灰度化 -> Haar 检测 -> 提取人脸 ROI -> 标签组织 -> LBPH 训练`

这里关注的是：你如何从训练集里提取尽量一致的人脸区域，并把它们稳定地交给识别器学习。

#### 验证 / 预测流水线

`验证图像 -> 灰度化 -> Haar 检测 -> 提取人脸 ROI -> 输入已训练好的 LBPH -> 得到预测标签`

这里关注的是：在不重新训练模型的前提下，验证集样本经过检测和裁剪后，识别结果是否仍然稳定。

## 各步骤在做什么

### 1. 读取图像

图像仍然只是像素矩阵，但在人脸任务里，你更关心的是其中局部区域，而不是整张图。

### 2. 灰度预处理

经典 Haar 检测通常在灰度图上进行，因为它更关注结构与亮度变化，而不是颜色本身。

### 3. Haar 检测

这一步的目标是找到可能的人脸区域。

你需要重点观察：

- 误检
- 漏检
- 参数变化对检测框数量的影响

### 4. ROI 提取

检测到的人脸区域会被裁成 ROI，后续识别阶段通常依赖这些局部区域，而不是原图全局。

### 5. 标签组织

你需要把每张训练图像与它所属的人名标签对应起来。

### 6. LBPH 训练

经典识别方法会根据训练样本建立每个标签的特征模式。

### 7. 验证集预测

最后再用验证集去观察：

- 哪些人容易识别正确
- 哪些样本容易混淆
- 检测质量是否影响识别结果

## 经典方法的教学价值

你学习这一阶段，不是为了追求当前最强方案，而是为了理解：

- 数据集为什么重要
- 检测和识别为什么是两段流程
- 为什么输入质量决定下游结果
- 为什么视觉任务要重视验证集和错误分析

## 经典方法的局限

你应该主动观察这些限制：

- 光照变化敏感
- 姿态变化敏感
- 遮挡敏感
- 样本不一致时容易混淆
- 对复杂现实场景鲁棒性有限

## Python 与 C++ 如何对应

### Python 先做什么

- 快速打通整条流程
- 快速看检测效果
- 快速建立训练 / 验证实验闭环

### C++ 再做什么

- 更明确组织检测器、训练数据、标签映射和预测流程
- 对比相同逻辑在工程实现上的差异

### 对照时建议重点看

- 图像读取方式
- 标签映射组织方式
- 检测结果如何进入识别阶段
- Python 与 C++ 版本是否使用同一组数据和参数

## 你在实现前要先回答的问题

1. 你这次是先做检测，还是先做完整识别闭环？
2. 你的标签映射规则是否清晰？
3. 你准备如何记录误检、漏检和误识别案例？
4. 你是否会先完成 Python，再迁移到 C++？
