# Face Dataset Notes

## 目标

在写人脸检测和识别代码之前，先明确当前仓库里的人脸数据如何组织，以及你后续应该如何使用这些数据。

## 当前已有数据结构

仓库已经提供了两类目录：

- `resources/faces/train/`
- `resources/faces/val/`

这说明当前资源已经天然区分了：

- 训练数据
- 验证数据

这是一个很好的教学结构，因为它能帮助你从一开始就建立“训练”和“验证”分开的意识。

## 训练集与验证集分别做什么

### 训练集

作用：

- 用来学习每个人的特征模式
- 用来建立标签与图像样本之间的关系

### 验证集

作用：

- 不参与训练
- 用来检验模型是否真的学到了区分能力
- 用来观察误识别和失败案例

## 你后续整理样本时要遵守的规则

1. 同一个人的图片必须放在同一个标签目录下
2. 训练集和验证集不要混用
3. 不要一开始就追求大量样本，先保证标签正确
4. 如果图片太模糊、角度太极端、遮挡太严重，要记录它是否属于异常样本
5. 如果检测阶段提取 ROI，人脸裁剪方式应尽量保持一致

## 当前资源能支持什么

根据当前目录，你已经可以练习：

- Haar Cascade 人脸检测
- 按类别读取训练数据
- 构建标签映射
- 在验证集上做经典识别测试

## 你需要特别注意的地方

### 1. 目录命名风格可能不完全一致

你不要只停留在“可能不一致”的提醒上，而是要在正式建立标签映射之前，先把命名规范定死。

例如你需要留意这类情况：

- 训练集里目录名可能是 `Ben Afflek`
- 验证集里目录名可能是 `ben_afflek`

如果你直接把原始目录名当成标签，这两者就会被错误地当成两个不同的人。

更稳妥的做法是先统一一套规范，例如：

1. 全部转成小写
2. 把连续空格替换成单个下划线
3. 去掉目录名前后的空白
4. 在 train 和 val 上都使用同一套归一化规则

也就是说，你最终做标签映射时，应该优先把 `Ben Afflek` 和 `ben_afflek` 都归一成同一个标签，比如 `ben_afflek`。

### 2. 检测质量会直接影响识别质量

如果检测框位置不稳定，后续 ROI 质量就会下降，识别结果也会受影响。

### 3. 这是一套教学资源，不是生产级基准集

你的目标不是追求“最强准确率”，而是：

- 理解完整流程
- 能解释成功与失败原因
- 明白经典方法的价值和限制

## Python 与 C++ 如何对应

### Python

适合先完成：

- 快速读取目录
- 快速建立标签映射
- 快速试验检测与识别流程

### C++

适合再完成：

- 更明确地组织类别、标签、图像读取逻辑
- 更清楚地理解训练数据是如何进入模型的

## 进入下一步前的自检

在开始写 `face_detection_with_haar` 或 `face_recognition_with_lbph` 之前，先确认：

- 你已经理解 train / val 的区别
- 你已经看过几类样本图片的实际内容
- 你已经决定标签如何从目录名映射出来
- 你知道自己的目标是“解释流程”，不是“刷高分”
