# 实验：小型实时综合项目

## 实验目标

把前面学过的读取、预处理、边缘/轮廓提取、过滤和可视化串起来，完成一个可运行、可解释的小型视频处理项目。

## 对应代码

- Python：`python/mini_project_live_pipeline.py`
- C++：`cpp/mini_project_live_pipeline.cpp`

## 第一性原理

综合项目的本质不是“功能越多越好”，而是：

- 输入是什么
- 每帧经过了哪些明确步骤
- 输出想表达什么
- 为什么这条处理链路是合理的

一个好的小项目，应该让你能清楚说明整条 pipeline，而不是堆很多操作却说不清逻辑。

## 实验步骤

1. 先从 `mini_project_ideas.md` 中选一个范围可控的方向
2. 明确输入视频、处理链路和输出目标
3. 先在纸面或文档里画出你的 frame loop
4. 先完成 Python 最短可运行版本
5. 观察失败案例并调整参数或流程
6. 再在 C++ 中复现同一项目
7. 最后总结项目的瓶颈和改进方向

## 需要观察的点

- 哪一步最影响整体效果
- 哪一步最影响实时性能
- 输出结果是否足够清晰可解释
- 参数是否在不同片段中依然稳定
- Python 和 C++ 的开发体验分别有什么不同

## 预期效果

完成后你应该能：

- 独立说明一个小型视频项目的输入、处理链和输出
- 让项目在已有视频资源上稳定运行
- 识别项目当前的主要限制和下一步改进方向

## 常见问题

### 1. 项目范围越做越大

这通常不是进步，而是失控。当前阶段更重要的是完成一个闭环，而不是做一个“大而全”的项目。

### 2. 项目能跑，但说不清为什么这样设计

说明你需要先回到 pipeline 设计本身，把每一步的作用写清楚。

### 3. 某一步效果很好，但整体项目不稳定

说明“局部成功”不等于“整体流程稳定”，你需要重新审视处理顺序与参数依赖。

## 实验报告模板

完成后建议你记录：

1. 项目目标
2. 输入资源
3. 每帧处理链路
4. 输出效果
5. 最常见失败案例
6. 当前性能瓶颈
7. 如果继续做，你的下一步优化计划是什么
