# Video Pipeline Design

## 目标

帮助你把前面静态图像阶段学到的处理方法，迁移到连续视频帧中，建立实时视觉系统的基本数据流思维。

## 图像变成视频后，问题发生了什么变化

静态图像处理时，你通常只处理一张矩阵。

视频处理时，你面对的是：

- 一串连续到来的图像帧
- 每一帧都要在有限时间内完成处理
- 处理顺序会影响实时显示体验
- 参数不稳定时，结果会在帧与帧之间抖动

所以视频处理不是“把图片代码套个循环”这么简单，而是要开始考虑：

- 每帧如何读取
- 每帧如何处理
- 每帧如何显示
- 什么时候退出
- 哪些步骤会拖慢整体速度

## 一条标准 frame loop

你后续的实时实验都可以围绕这条基本链路设计：

`打开视频源 -> 逐帧读取 -> 预处理 -> 分析 -> 标注 -> 显示 -> 按键退出或读到结尾`

## 你在每一帧上做的其实还是图像处理

从第一性原理看，视频处理仍然是在处理图像，只不过你要把同一套单帧算法反复应用到连续帧上。

也就是说：

- 边缘检测还是边缘检测
- 轮廓提取还是轮廓提取
- 只是你现在必须关心它在连续时间上的稳定性

## 为什么实时阶段更容易暴露问题

### 1. 参数波动会被放大

在一张图上勉强可用的参数，放到视频里可能会让结果在相邻帧之间不断抖动。

### 2. 计算成本会累积

单张图上稍慢一点没关系，但视频里每帧都慢一点，就会直接影响整体流畅度。

### 3. 显示与退出逻辑必须明确

如果读取、显示、按键监听的顺序不清楚，程序就容易卡住或无法正常退出。

## 推荐的学习迁移路径

你可以这样把前面阶段的内容迁移到视频：

1. 先复习 `01_io_and_display/experiment_read_video.md`
2. 再把 `04` 或 `06` 阶段中的单帧算法嵌入逐帧循环
3. 先做最简单的实时边缘实验
4. 再做实时轮廓与过滤
5. 最后组合成一个小型综合项目

## Python 与 C++ 如何对应

### Python

适合先完成：

- 快速打通逐帧读取与显示
- 快速验证实时效果
- 快速调参数看稳定性

### C++

适合再完成：

- 更明确组织 frame loop
- 更清楚感受类型、函数拆分和运行过程
- 比较同一条实时管线在两种语言中的实现差异

## 实现时检查清单

开始写代码前先确认：

- 你是否已经确定输入视频
- 你是否已经定义每帧要做哪些步骤
- 你是否会显示中间结果或最终结果
- 你是否已经想好退出条件
- 你是否会在 Python 完成后再迁移到 C++
